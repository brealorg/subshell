Security

How to report a vulnerability without exposing sensitive details.

Do not report vulnerabilities publicly.

Use GitHub's private vulnerability reporting so details are not exposed in the public issue tracker.

Report a vulnerability privately

What to include

Provide enough information to reproduce and assess the issue, including affected Subshell version, Android version and relevant steps.

Do not include Reddit credentials, OAuth access or refresh tokens, cookies, passwords, private messages, signing material or other personal account data.

Supported builds

Before the first public beta there is no publicly supported Subshell build. After beta publication, security fixes target the newest public beta or release unless the release notes explicitly state otherwise.

Release authenticity

Public Android builds are distributed through GitHub Releases using the established Stable signing identity. Release assets include an SHA-256 sidecar so the exact APK can be checked after download.
