Security

How to report a vulnerability without exposing sensitive details, and how to check a download.

Do not report vulnerabilities publicly.

Use GitHub's private vulnerability reporting so details are not exposed in the public issue tracker.

Report a vulnerability privately

What to include

Enough to reproduce and assess the issue: the subshell version, Android version and the steps.

Do not include Reddit credentials, OAuth access or refresh tokens, cookies, passwords, private messages, signing material or other personal account data.

Supported builds

Security fixes target the newest public beta unless the release notes say otherwise.

Checking a download

Every release is signed with the same release key and published on GitHub Releases with three files: the APK, a .sha256 checksum and a release record (source commit, checks run, signing certificate digest). Compare the checksum before installing; the in-app update dialog shows the same value.

Android refuses to install an update signed with a different key, so an installed subshell only accepts genuine updates.
